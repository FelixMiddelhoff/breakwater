# BW003: renaming is not safe for a rolling deploy

`migrationBuilder.RenameColumn(...)` and `migrationBuilder.RenameTable(...)`
change a name that the previous application version still uses.

## Why it hurts

- The rename is instant for the database, but the previous application version
  keeps using the old name and fails on every query.
- EF Core generates a rename by itself when you rename a property or entity,
  so it is easy to ship without noticing.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.RenameColumn(name: "Mail", table: "Users", newName: "Email");
}
```

## Safe alternative

1. Add the new column (or table) and copy the data.
2. Deploy code that writes both and reads the new one.
3. In a later release, drop the old column (or table).

## When it is fine

The old application version is not running while the migration executes.
Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW003.severity = suggestion
```

## Not reported

Operations inside `Down`, and methods named `RenameColumn` or `RenameTable` on
types other than `MigrationBuilder`.
