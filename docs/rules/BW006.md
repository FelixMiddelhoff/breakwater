# BW006: AddColumn requires NOT NULL without a default

`migrationBuilder.AddColumn(...)` that is NOT NULL with no default value fails the
moment the table already has rows, because every existing row needs a value for
the new column and none was given.

## Why it hurts

- The migration fails outright on any table that is not empty.
- An old application version that does not know about the new column keeps
  inserting rows without it, which would violate the constraint too.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW006
    migrationBuilder.AddColumn<string>(
        name: "Sku",
        table: "Products",
        nullable: false);
}
```

## Safe alternative

Add the column as nullable, backfill every row, then constrain it to NOT NULL in a
later migration. Or give it a constant default value here, which every provider
can apply without a per-row computation (see BW016 for why a computed default is
different).

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW006.severity = suggestion
```

## Not reported

- The call carries `defaultValue` or `defaultValueSql`.
- The column is nullable.
- A column added to a table created earlier in the same migration: it is still
  empty, so there are no existing rows to violate the constraint.
