# BW018: dropping or restarting a schema/sequence can lose data or duplicate ids

`migrationBuilder.DropSchema(...)`, `DropSequence(...)`, `AlterSequence(...)` and
`RestartSequence(...)` can lose a sequence's current value, or produce duplicate
ids while an old application version still runs.

## Why it hurts

Dropping a schema removes everything in it with no way back. Dropping, altering or
restarting a sequence can reset or lose its current value, and an application
version still running against the old value can hand out ids that collide with
rows already written under the new one.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW018
    migrationBuilder.RestartSequence(name: "OrderNumbers", startValue: 1);
}
```

## Safe alternative

Confirm nothing still depends on the schema or sequence's current state before
dropping or restarting it; for a sequence, make sure no application version could
hand out an id from the old range after the restart.

## When it is fine

This is a Suggestion-tier rule (`Info` severity, IDE hint only, no build output) by
default. Raise it if you want it to fail the build:

```ini
dotnet_diagnostic.BW018.severity = warning
```

## Not reported

Nothing special beyond matching one of the four operations above.
