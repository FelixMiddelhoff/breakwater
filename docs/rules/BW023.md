# BW023: DropColumn and AddColumn on the same table look like an undetected rename

A `DropColumn` and an `AddColumn` on the same table in one migration is the shape
EF Core generates when a property is renamed *and* its type changes at the same
time, and EF cannot tell it apart from removing one property and adding another.

## Why it hurts

The data in the old column is silently lost, even though the developer's intent
was almost certainly a rename, not a drop-and-recreate.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW023
    migrationBuilder.DropColumn(name: "FullName", table: "Users");
    migrationBuilder.AddColumn<string>(name: "DisplayName", table: "Users", nullable: true);
}
```

## Safe alternative

If this really is a rename, use `migrationBuilder.RenameColumn(...)` instead (add
a follow-up migration to convert the type if it changed too). If it is really two
unrelated changes, this is a false positive and can be suppressed.

## When it is fine

Suppress it for a specific call with a reason once you have confirmed it is not a
rename:

```csharp
// breakwater: allow BW023 unrelated changes, verified with the author
migrationBuilder.DropColumn(name: "FullName", table: "Users");
```

Or lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW023.severity = suggestion
```

## Not reported

`DropColumn` alone, with no `AddColumn` on the same table in the same migration -
that is plain BW001 instead. When both fire on the same `DropColumn`, BW023 is more
specific and suppresses BW001 for that call (only one of the two is reported).
