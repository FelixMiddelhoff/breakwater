# BW032: EnsureCreated() is used in a project that also has migrations

A call to `Database.EnsureCreated()` anywhere in a compilation that also contains
at least one migration (a class deriving from `Migration`) is flagged: the two
do not mix.

## Why it hurts

`EnsureCreated()` builds the schema straight from the current model and never
records applied migrations. Any later call to `Database.Migrate()` on a database
it created either fails or silently does nothing, because EF Core has no
migration history to compare against.

## Example

```csharp
using Microsoft.EntityFrameworkCore.Infrastructure;
using Microsoft.EntityFrameworkCore.Migrations;

public class Startup
{
    public void Configure(DatabaseFacade database)
    {
        // breakwater: expect BW032
        database.EnsureCreated();
    }
}

public class InitialCreate : Migration
{
    protected override void Up(MigrationBuilder migrationBuilder) { }
}
```

## Safe alternative

Use `Database.Migrate()` (or apply migrations through the EF Core CLI/tooling)
instead, even for the very first deploy to a fresh database.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW032.severity = suggestion
```

## Not reported

- No class in the compilation derives from `Migration`: a project with no
  migrations at all is exactly what `EnsureCreated()` is meant for.
- Note: calling `Database.Migrate()` at application startup is not itself flagged
  by any rule - only `EnsureCreated()` alongside migrations is.
