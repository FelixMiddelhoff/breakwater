# BW026: AlterColumn adds or removes identity/value generation

An `AlterColumn` that chains a `.Annotation(...)` naming identity or value
generation (for example SQL Server's `SqlServer:Identity` or a
`ValueGenerationStrategy` annotation) not matched by the equivalent
`.OldAnnotation(...)`, or vice versa, cannot be applied in place on most
providers.

## Why it hurts

Value generation is baked into the column's storage on most providers; changing
it cannot be done with a plain `ALTER COLUMN`, and the generated script either
fails or rebuilds the whole table.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW026
    migrationBuilder.AlterColumn<int>(name: "Id", table: "Orders")
        .Annotation("SqlServer:Identity", "1, 1");
}
```

## Safe alternative

Add a new column with the desired generation, backfill it, then switch the code
and drop the old column.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW026.severity = suggestion
```

## Not reported

- The generation-related annotation is present on both sides (`.Annotation(...)`
  and the matching `.OldAnnotation(...)`), or on neither.
- This rule shares one `AlterColumn` call with BW004, BW005 and BW015: only the
  most specific of the four is reported for the same call.
