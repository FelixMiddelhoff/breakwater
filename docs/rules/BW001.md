# BW001: dropping a column is not safe for a rolling deploy

`migrationBuilder.DropColumn(...)` removes the column and everything in it.

## Why it hurts

- The data is gone for good.
- During a rolling deploy the previous application version keeps running
  against the new schema. Every query that mentions the column fails.
- EF Core generates `DropColumn` on its own when you delete a property from an
  entity, so it is easy to ship without noticing.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.DropColumn(name: "Email", table: "Users");
}
```

## Safe alternative

Split the change over two releases (expand and contract):

1. Release 1: stop reading and writing the column in the code. Keep the column.
2. Release 2: once no running version uses it, drop the column in a migration
   and suppress this warning for that line.

## When it is fine

The old application version is not running while the migration executes (you
stop the app first), or the column is known to be unused. Suppress it with
`#pragma warning disable BW001` around the call, or lower the severity in
`.editorconfig`:

```ini
dotnet_diagnostic.BW001.severity = suggestion
```

## Not reported

Operations inside `Down`, and methods named `DropColumn` on types other than
`MigrationBuilder`.
