# BW033: raw SQL creates a login/user with a password, or embeds a connection string

`migrationBuilder.Sql(...)` text matching a `PASSWORD =` / `IDENTIFIED BY` clause,
or a connection string containing both a server and a password, puts a credential
straight into source control.

## Why it hurts

Whatever this migration writes to the database, it also writes to source control,
and to every environment and every developer machine that checks it out.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW033
    migrationBuilder.Sql("CREATE LOGIN reporting_user WITH PASSWORD = 'Sup3rSecret!'");
}
```

## Safe alternative

Create the login/user through a secret-managed deployment step instead of a
migration, or generate the password separately (for example a deployment
pipeline secret) and never commit it.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW033.severity = suggestion
```

## Not reported

- The SQL text is not a compile-time constant.
- Neither a `PASSWORD =`/`IDENTIFIED BY` clause nor a connection string
  (`Server=...Password=...` / `Data Source=...Pwd=...` shape) is present.
