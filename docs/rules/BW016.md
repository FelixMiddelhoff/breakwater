# BW016: AddColumn default is computed per row on PostgreSQL

On PostgreSQL, a constant default is applied as metadata only and is instant, but
a volatile default such as `now()` or `gen_random_uuid()` has to be computed and
written for every existing row, rewriting the whole table.

## Why it hurts

A volatile default is computed per row, which rewrites the entire table and holds
a lock for the duration - even though a constant default on the same column would
have been instant.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    if (migrationBuilder.IsNpgsql())
    {
        // breakwater: expect BW016
        migrationBuilder.AddColumn<System.DateTime>(
            name: "CreatedAt",
            table: "Users",
            defaultValueSql: "now()");
    }
}
```

## Safe alternative

Use a constant default here (for example a fixed timestamp), or backfill the
computed value in a separate step after adding the column as nullable.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW016.severity = suggestion
```

## Not reported

- The call is not inside a known `if (migrationBuilder.IsNpgsql())` guard: provider
  unknown, silent per "silent when unsure".
- `defaultValueSql` does not contain one of the recognized volatile functions
  (`now()`, `current_timestamp`, `clock_timestamp()`, `gen_random_uuid()`,
  `uuid_generate_v4()`, `random()`, `nextval(...)`) - this list is not exhaustive
  by design, so an unrecognized function stays silent rather than guessed at.
- The column is on a table created earlier in the same migration.
- `defaultValue` (a constant) is used instead of `defaultValueSql`.
