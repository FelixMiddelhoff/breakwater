# BW031: raw SQL contains a GO/USE batch separator

`GO` (a line by itself, SSMS/sqlcmd's batch separator) and `USE` (a database
switch) inside `migrationBuilder.Sql(...)` are not valid inside a single ADO.NET
command: EF sends the whole string as one command and it fails at runtime, not at
build time.

## Why it hurts

`GO` and `USE` are recognized by SSMS/sqlcmd, not by the ADO.NET command EF sends
the string through. The migration compiles and looks fine, then fails at runtime
with a SQL syntax error.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW031
    migrationBuilder.Sql("""
        ALTER TABLE Orders ADD Notes nvarchar(max) NULL
        GO
        UPDATE Orders SET Notes = ''
        """);
}
```

## Safe alternative

Split the string into separate `migrationBuilder.Sql(...)` calls, one per batch,
with no `GO` between them.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW031.severity = suggestion
```

## Not reported

- `GO` or `USE` appearing only inside a string literal or comment.
- The SQL text is not a compile-time constant.
