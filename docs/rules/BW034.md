# BW034: raw SQL disables an integrity check or drops the database

`migrationBuilder.Sql(...)` text containing `NOCHECK CONSTRAINT`,
`DISABLE TRIGGER`, `SET FOREIGN_KEY_CHECKS = 0`, or `DROP DATABASE` turns off a
safety mechanism, or destroys the database outright, without anyone noticing until
something downstream breaks.

## Why it hurts

Turning off constraint or trigger enforcement, or disabling foreign key checks,
means rows can be written that violate the rules the schema is supposed to
guarantee - and nothing reports it until something downstream breaks.
`DROP DATABASE` is unrecoverable.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW034
    migrationBuilder.Sql("ALTER TABLE Orders NOCHECK CONSTRAINT FK_Orders_Customers");
}
```

## Safe alternative

Re-enable the check immediately after, in the same migration, or avoid disabling
it at all. Never run `DROP DATABASE` from a migration.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW034.severity = suggestion
```

## Not reported

- The SQL text is not a compile-time constant.
- None of the four recognized patterns are present.

This rule can co-fire with BW010 on the same statement (for example
`DROP DATABASE` also matches BW010's `DROP` check) - that is intentional, since
each rule flags a different problem with the same statement.
