# BW022: migration mixes several risky operations on the same table

When a migration performs three or more risky operations on the same table,
Breakwater flags the last one as an opportunity to split the migration up.

## Why it hurts

Several locking operations on the same table in one migration add up: each one's
lock time stacks on the others.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.AddColumn<string>(name: "Notes", table: "Orders", nullable: true);
    migrationBuilder.DropColumn(name: "LegacyFlag", table: "Orders");
    // breakwater: expect BW022
    migrationBuilder.AlterColumn<int>(name: "Priority", table: "Orders", nullable: true, oldNullable: false);
}
```

## Safe alternative

Split the operations into separate migrations, so each one runs (and can be
rolled back) independently, keeping any single lock as short as possible.

## When it is fine

This is a Suggestion-tier rule (`Info` severity, IDE hint only, no build output) by
default. Raise it if you want it to fail the build:

```ini
dotnet_diagnostic.BW022.severity = warning
```

## Not reported

- Fewer than three risky operations on the same table in the migration.
- An operation that a more specific rule already reported on: BW022 is advisory
  and only appears when nothing more specific fired for that exact operation.
  Since almost every risky operation already has its own rule, this in practice
  mostly surfaces for an operation a more specific rule stays silent on (for
  example a nullable `AddColumn` with no default).
- It reports once per table, on the last qualifying risky operation seen for it -
  not once per operation.
