# BW011: Down is empty or always throws

A migration whose `Down` method is empty, or does nothing but
`throw new NotSupportedException(...)`, cannot be rolled back.

## Why it hurts

Without a working `Down`, a bad deploy cannot be rolled back with
`dotnet ef database update` to the previous migration; someone has to write and
test the reverse by hand, under pressure, after something has already gone wrong.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.AddColumn<string>(name: "Nickname", table: "Users", nullable: true);
}

// breakwater: expect BW011
protected override void Down(MigrationBuilder migrationBuilder)
{
}
```

## Safe alternative

Implement the reverse operation in `Down` (here, `DropColumn`), or explain in a
comment why rolling back is intentionally unsupported and keep the pragma.

## When it is fine

This rule is informational and **off by default**: many teams intentionally never
roll back a migration and can ignore it entirely. It only reports when
`breakwater_profile = strict` is set in `.editorconfig`:

```ini
breakwater_profile = strict
```

Once enabled, lower it like any other rule:

```ini
dotnet_diagnostic.BW011.severity = suggestion
```

## Not reported

- Under the default `recommended` profile, this rule never reports, regardless of
  `Down`'s content.
- A `Down` with any statement other than a lone `throw new NotSupportedException(...)`.
- A class that does not derive from `Migration`.
