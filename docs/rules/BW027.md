# BW027: CreateIndex(unique: true) can fail on existing duplicate data

Unlike a plain index, a unique index on an existing table fails the whole
migration if any two existing rows already share a value, and it still holds a
lock while it builds.

## Why it hurts

The migration fails outright on any duplicate, and the lock is held for the build
regardless of whether it succeeds.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW027
    migrationBuilder.CreateIndex(
        name: "IX_Users_Email",
        table: "Users",
        columns: new[] { "Email" },
        unique: true);
}
```

## Safe alternative

Check for duplicates first (or clean them up), and consider building the index
concurrently/online (see BW007) before adding uniqueness.

## When it is fine

This is a Suggestion-tier rule (`Info` severity, IDE hint only, no build output) by
default. Raise it if you want it to fail the build:

```ini
dotnet_diagnostic.BW027.severity = warning
```

## Not reported

- `unique` is not set to `true`.
- The index is on a table created earlier in the same migration.
- The indexed column was added as nullable in the same migration: there is no
  existing data yet to conflict on.
