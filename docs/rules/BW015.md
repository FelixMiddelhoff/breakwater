# BW015: AlterColumn changes the collation

`migrationBuilder.AlterColumn(...)` with a `collation` that differs from
`oldCollation` makes most providers rewrite the column's data and every index that
touches it.

## Why it hurts

SQL Server and most other providers rewrite the column and its indexes to apply a
new collation. On a large table this holds a lock for a long time.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW015
    migrationBuilder.AlterColumn<string>(
        name: "Name",
        table: "Products",
        collation: "Latin1_General_CI_AS",
        oldCollation: "SQL_Latin1_General_CP1_CI_AS");
}
```

## Safe alternative

Consider whether the comparison behaviour can instead be handled in application
code or a new column, rather than an in-place collation change.

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW015.severity = suggestion
```

## Not reported

- `collation` and `oldCollation` are the same, or either is unknown.
- A column on a table created earlier in the same migration.
- This rule shares one `AlterColumn` call with BW004, BW005 and BW026: only the
  most specific of the four is reported for the same call.
