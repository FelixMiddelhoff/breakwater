# BW007: CreateIndex without an online/concurrent build

`migrationBuilder.CreateIndex(...)` on an existing table blocks writes to the
table for as long as the build takes, unless the provider's online/concurrent
build is explicitly opted into.

## Why it hurts

A plain index build takes a lock that blocks writes for the duration, which on a
large table can be minutes or hours.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // breakwater: expect BW007
    migrationBuilder.CreateIndex(
        name: "IX_Orders_CustomerId",
        table: "Orders",
        columns: new[] { "CustomerId" });
}
```

## Safe alternative

- PostgreSQL: chain `.Annotation("Npgsql:CreatedConcurrently", true)` and set
  `migrationBuilder.SuppressTransaction = true;` in the same `Up` method.
- SQL Server (Enterprise/Developer editions): chain
  `.Annotation("SqlServer:Online", true)`.

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.SuppressTransaction = true;
    migrationBuilder.CreateIndex(
        name: "IX_Orders_CustomerId",
        table: "Orders",
        columns: new[] { "CustomerId" })
        .Annotation("Npgsql:CreatedConcurrently", true);
}
```

## When it is fine

Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW007.severity = suggestion
```

## Not reported

- The `Npgsql:CreatedConcurrently` annotation is chained on the call *and*
  `migrationBuilder.SuppressTransaction = true;` appears anywhere in the same `Up`
  method.
- The `SqlServer:Online` annotation is chained on the call.
- The index is on a table created earlier in the same migration: it is still
  empty.
