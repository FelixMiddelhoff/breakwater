# BW002: dropping a table is not safe for a rolling deploy

`migrationBuilder.DropTable(...)` removes the table and all its rows.

## Why it hurts

- The data is gone for good.
- During a rolling deploy the previous application version keeps running
  against the new schema. Every query that mentions the table fails.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.DropTable(name: "Orders", schema: "shop");
}
```

## Safe alternative

1. Release 1: stop using the table in the code. Keep the table.
2. Release 2: once no running version uses it, take a backup if the data
   matters and drop the table in a migration.

## When it is fine

The old application version is not running while the migration executes, or
the table is known to be unused. Lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW002.severity = suggestion
```

## Not reported

Operations inside `Down`, and methods named `DropTable` on types other than
`MigrationBuilder`.
