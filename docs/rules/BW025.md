# BW025: AddForeignKey references a column added with a placeholder default

An `AddForeignKey` on a column that was added in the *same* migration with a
placeholder default (`0`, `""`, or `Guid.Empty`) points every existing row at a
parent that almost certainly does not exist for that placeholder value.

## Why it hurts

Every existing row now has the placeholder value in the new column, and the
foreign key requires a matching parent row for it. Unless a parent row with that
exact key already exists, the migration fails when it validates the constraint.

## Example

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.AddColumn<int>(name: "CustomerId", table: "Orders", nullable: false, defaultValue: 0);

    // breakwater: expect BW025
    migrationBuilder.AddForeignKey(
        name: "FK_Orders_Customers",
        table: "Orders",
        columns: new[] { "CustomerId" },
        principalTable: "Customers");
}
```

## Safe alternative

Backfill the column with real parent ids before adding the foreign key, or add it
as `NOT VALID` (PostgreSQL) and validate once the backfill is done.

## When it is fine

A parent row with that exact placeholder key genuinely exists (for example a
sentinel "Unknown Customer" row with id `0`). Suppress it with a reason:

```csharp
// breakwater: allow BW025 row 0 is the seeded "Unknown Customer" sentinel
```

Or lower the severity in `.editorconfig`:

```ini
dotnet_diagnostic.BW025.severity = suggestion
```

## Not reported

- The referenced column was not added in the same migration, or was added without
  a placeholder default (`0`, empty string, or `Guid.Empty`).
- The foreign key's column cannot be determined.
